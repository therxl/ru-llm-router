# Русский LLM-роутер

Лёгкий роутер на **Go**, который даёт приложениям единый интерфейс для работы с LLM-подключениями. Пользователь сам выбирает модели, провайдеров и размещение: внешний API, локальный runtime или собственная инфраструктура. Роутер не хостит модели, не оплачивает inference и не навязывает белый список подключений.

## Текущий статус: ранний MVP

Сейчас реализованы HTTP-сервер, YAML-конфигурация, явный выбор подключения, mock-провайдер и тесты. Mock возвращает тестовый текст и **не вызывает настоящую нейросеть**. Реальный API-адаптер, автоматическая маршрутизация и fallback пока не реализованы.

## Быстрый старт

Требуется Go 1.23 или новее.

```bash
go mod tidy
go test ./...
go run ./cmd/router -config configs/example.yaml
```

В другом терминале проверь сервер:

```bash
curl http://127.0.0.1:8080/health
```

Отправь тестовый запрос:

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "mock-default",
    "messages": [{"role": "user", "content": "Привет!"}]
  }'
```

В ответе будет JSON в минимальном формате Chat Completions с текстом от mock-провайдера.

## Конфигурация и секреты

Пример подключения находится в [configs/example.yaml](configs/example.yaml). Для локальных настроек создай отдельный файл и не коммить его. Секреты следует передавать через переменные окружения; не помещай API-ключи в YAML, исходный код или Git.

Например, будущий адаптер сможет ссылаться на имя переменной:

```yaml
connections:
  - name: my-provider
    provider: openai-compatible
    model: my-model
    base_url: https://example.invalid/v1
    api_key_env: MY_PROVIDER_API_KEY
```

Это пример будущего адаптера, а не доступный сейчас тип провайдера. Пока поддерживается только `provider: mock`.

## Что уже есть

- `GET /health` — проверка процесса.
- `POST /v1/chat/completions` — запрос с `model` и `messages`.
- Маршрутизация по имени подключения или model ID, заданному в YAML.
- Валидация базовой формы запроса и нормализованные JSON-ошибки.
- Тесты конфигурации, маршрутизации и HTTP handler.

Ограничения: нет аутентификации клиента, TLS, streaming, tools, мультимодальных сообщений, автоматического выбора модели и fallback. Не выставляй сервис в публичную сеть.

## Направление проекта

- Единый API для пользовательских LLM-подключений.
- Явный выбор модели и, позднее, настраиваемый автоматический выбор.
- Поддержка внешних и локальных endpoint без запуска моделей самим роутером.
- Опциональные пользовательские политики и телеметрия.
