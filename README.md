# Русский LLM-роутер

Единый API для приложений, который выбирает языковую модель под задачу с учётом качества, стоимости, задержки и доступности провайдеров.

**Статус:** MVP / прототип. Целевой стартовый профиль — около 1 000 запросов в сутки, преимущественно coding-задачи. На первом этапе рекомендуются внешние API-провайдеры, а не собственная GPU-инфраструктура.

## Поток запроса

1. Клиент отправляет запрос в единый API.
2. Роутер определяет класс задачи и ограничения: качество, бюджет, задержку, контекст.
3. Из каталога выбираются подходящие модели, затем применяется политика маршрутизации.
4. Адаптер вызывает провайдера; при временной ошибке возможен fallback.
5. Клиент получает нормализованный ответ, а система записывает метрики и расчётную стоимость.

## Исходные предположения

- 1 000 запросов в сутки.
- Coding-профиль: в среднем 4 000 входных и 1 000 выходных токенов на запрос.
- Базовый сценарий: один вызов LLM на запрос.
- Это планировочные предположения, а не измеренные значения.

При этих допущениях: примерно 5 млн токенов в сутки (4 млн входных и 1 млн выходных) и 150 млн токенов за 30 дней. Стоимость зависит от актуальных тарифов выбранных моделей и провайдеров.

## Принципы

1. Бенчмарки помогают отбирать кандидатов; окончательный выбор проверяется на собственном наборе задач.
2. Маршрутизация учитывает качество, задержку, доступность и цену.
3. Retry/fallback ограничены по числу попыток и бюджету.
4. Не записывать секреты и полный текст запросов по умолчанию.
5. Измерять качество и фактическую экономию относительно фиксированного baseline.

## Текущий статус
