# Русский LLM-роутер

Лёгкий роутер на **Go**, который даёт приложениям единый интерфейс для работы с моделями. Пользователь сам выбирает, какие модели подключать и где запускать: через внешнего провайдера, на собственной машине или на своей инфраструктуре. Роутер помогает направить задачу к подходящему подключению, но не навязывает набор моделей и не ограничивает их использование сверх настроенных пользователем правил.

## Что проект должен делать

- Предоставлять единый API для разных моделей и провайдеров.
- Помогать выбирать модель под задачу: coding, общий вопрос, извлечение данных и другие профили.
- Позволять пользователю задавать приоритеты: цена, качество, задержка, доступность или конкретная модель.
- Подключать локальные модели через совместимый локальный endpoint/runtime, не оплачивая и не хостя их за пользователя.
- Показывать оценку нагрузки и стоимости там, где доступны тарифы и данные о токенах.
- Оставлять решение о подключениях, лимитах и политике использования за пользователем.

## Планирование нагрузки

GitHub README не исполняет JavaScript, поэтому встроенные интерактивные поля здесь не работают. Вместо неработающей ссылки на GitHub Pages ниже приведён набор сценариев, который можно использовать как быстрый ориентир; подробные формулы и допущения — в [расчёте нагрузки](docs/load-calculation.md).

Базовые допущения для coding-профиля: 4 000 входных токенов и 1 000 выходных токенов на запрос, один вызов модели на запрос.

| Запросов в сутки | Средний RPS | Входных токенов/сутки | Выходных токенов/сутки | Всего токенов/сутки |
|---:|---:|---:|---:|---:|
| 1 000 | 0,0116 | 4 млн | 1 млн | 5 млн |
| 10 000 | 0,1157 | 40 млн | 10 млн | 50 млн |
| 100 000 | 1,1574 | 400 млн | 100 млн | 500 млн |
| 1 000 000 | 11,5741 | 4 млрд | 1 млрд | 5 млрд |

Формула примерной стоимости за сутки: `(входные токены / 1 000 000 × тариф входа) + (выходные токены / 1 000 000 × тариф выхода)`. Для локальных моделей цена API-токенов может быть неприменима: расходы на железо, электроэнергию и эксплуатацию несёт владелец локального окружения. Роутер не предполагает, что локальный запуск бесплатен, и не берёт эти расходы на себя.

## Предлагаемая архитектура

1. **Go API gateway** — единый интерфейс, валидация и request ID.
2. **Конфигурация подключений** — пользовательские endpoint, модели, возможности и необязательные тарифы.
3. **Лёгкая маршрутизация** — выбор из доступных пользователю подключений на основе задачи и его предпочтений.
4. **Адаптеры** — нормализация различающихся API.
5. **Телеметрия по желанию** — latency, токены, ошибки и приблизительная стоимость без обязательного сохранения содержимого запросов.

Роутер не должен требовать централизованной оплаты всех моделей или собственного каталога, ограничивающего выбор пользователя. Каталог и готовые профили могут быть удобными подсказками, но подключение произвольной совместимой модели остаётся возможным.

## Статус

Репозиторий пока содержит требования, предварительные расчёты и архитектурное описание. Следующий шаг — минимальный Go API, конфигурация пользовательских подключений, совместимый адаптер и тесты маршрутизации. Это ещё не production-сервис.
