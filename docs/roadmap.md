## Этап 3 — готовность к пилоту
- [ ] Добавить dashboard по стоимости, latency, ошибкам и классам задач.
- [ ] Провести нагрузочный тест на ожидаемом пике.
- [ ] Добавить rate limiting, circuit breaker и ротацию секретов.
- [ ] Проверить приватность логов, retention и обработку персональных данных.
- [ ] Добавить runbook для недоступности провайдера и превышения бюджета.

**Критерий выхода:** деградация контролируется, расходы ограничены, ошибки наблюдаемы.

## Первые 5 инженерных задач
1. Определить API-контракт и схему конфигурации моделей.
2. Реализовать интерфейс ProviderAdapter и мок-провайдер.
3. Добавить два профиля маршрутизации с детерминированными правилами.
4. Добавить метрики и unit-тесты расчёта токенов/стоимости.
5. Реализовать один реальный адаптер и интеграционные тесты с моками.

## Что пока не делать
- Не обучать собственную базовую модель.
- Не поднимать GPU-кластер до подтверждения потребности.
- Не обещать экономию без измерения качества и реальных тарифов.
- Не добавлять много провайдеров до появления надёжного интерфейса адаптера.
