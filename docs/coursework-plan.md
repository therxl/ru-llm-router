# План разработки веб-приложения для курсовой

## Тема

«Разработка веб-приложения для диалогового взаимодействия с выбранной большой языковой моделью».

## Цель курсовой

Создать веб-приложение, позволяющее пользователю вести диалог с выбранной большой языковой моделью через единый серверный API.

## Границы курсовой

В курсовую входят:
- веб-интерфейс чата;
- ручной выбор доступной модели;
- два способа настройки подключений: готовые подключения из конфигурации и пользовательские подключения с собственным API-ключом;
- передача сообщений и получение ответов;
- история диалогов;
- базовая обработка ошибок и отображение выбранной модели;
- тестирование и инструкция запуска.

В курсовую не входят: автоматический выбор модели, интеллектуальная маршрутизация, автоматический fallback, API для автономных агентов, коммерческий биллинг и десктопная оболочка. Эти направления остаются возможным развитием ВКР и следующих версий.

## Принципы архитектуры

Сохраняем существующее Go-ядро и развиваем его, не переписывая:
- cmd/router — запуск HTTP-сервера;
- internal/api — HTTP API для интерфейса;
- internal/config — конфигурация подключений;
- internal/router — явный выбор подключения по имени или model ID;
- internal/provider — общий интерфейс провайдера;
- internal/provider/mock — тестовый провайдер.

Добавляем постепенно:
- реальный адаптер к API, совместимому с форматом Chat Completions;
- API для получения списка доступных моделей/подключений;
- веб-клиент в web/;
- слой хранения диалогов и сообщений;
- безопасное управление пользовательскими секретами.

## Два способа подключения моделей

### 1. Готовые подключения

Администратор локального экземпляра заранее задаёт подключения в YAML-конфигурации. Интерфейс получает список доступных подключений и позволяет выбрать одно из них.

### 2. Пользовательские подключения

Пользователь добавляет endpoint, идентификатор модели и API-ключ. Секрет передаётся только серверной части и не возвращается браузеру. На первом локальном этапе допускается настройка ключа через переменную окружения; полноценное управление ключами из интерфейса требует отдельного защищённого хранилища и не должно реализовываться через localStorage или открытый YAML-файл.

## Этапы реализации

1. Ревизия и закрепление текущего MVP: тесты, конфигурация, обработка ошибок, документация.
2. Реализация первого настоящего провайдера через совместимый Chat Completions API; mock остаётся для тестов.
3. Добавление endpoint для безопасного получения списка доступных подключений без секретов.
4. Создание веб-интерфейса чата с ручным выбором модели.
5. Реализация диалогов и хранения истории.
6. Добавление пользовательских подключений и защищённого хранения API-ключей.
7. Интеграционные тесты, инструкция запуска и подготовка демонстрации курсовой.

## Технологии

- Backend: Go и стандартная библиотека HTTP.
- Frontend: React + TypeScript.
- Хранение истории: SQLite.
- Конфигурация сервера: YAML.
- Секреты: переменные окружения на начальном этапе; защищённое локальное хранилище при реализации управления ключами из UI.

## Критерии готовности курсовой

- приложение запускается локально на Windows;
- пользователь открывает веб-чат в браузере;
- интерфейс показывает доступные подключения;
- пользователь выбирает модель и отправляет сообщение;
- ответ отображается в чате;
- можно вести несколько диалогов и просматривать историю;
- ошибки подключения и неверные настройки отображаются понятным образом;
- API-ключи не попадают в репозиторий и не выдаются браузеру;
- автоматические тесты проходят.

## Развитие в рамках ВКР

На базе курсовой версии можно реализовать:
- интеллектуальную маршрутизацию по типу и сложности задачи;
- автоматический выбор модели с учётом контекста, цены и доступности;
- управление контекстом и перенос диалога между моделями;
- резервные модели и политики повторных запросов;
- единый API для внешних приложений и AI-агентов;
- расширенный мониторинг токенов и расходов.

Веб-интерфейс курсовой при этом остаётся одним из клиентов общего Go-ядра.
