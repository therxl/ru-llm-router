# Локальная разработка MVP

## Требования

- Go 1.23 или новее.
- Доступ к GitHub для клонирования репозитория.
- На первом этапе внешний API-ключ не нужен: используется mock-провайдер.

## Запуск

Из корня репозитория:

```bash
go mod tidy
go test ./...
go run ./cmd/router -config configs/example.yaml
```

По умолчанию сервис слушает `127.0.0.1:8080`. Проверка здоровья:

```bash
curl http://127.0.0.1:8080/health
```

Ожидаемый ответ: `{"status":"ok"}`.

## Проверка mock-запроса

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "mock-default",
    "messages": [
      {"role": "user", "content": "Привет, роутер!"}
    ]
  }'
```

Ответ содержит стандартные поля Chat Completions и текст с префиксом `Mock response`. Это тестовый ответ, не результат реальной языковой модели.

## Конфигурация

Скопируйте `configs/example.yaml` в локальный файл, который не попадёт в Git, и передайте его через `-config`. Подключения задаются пользователем. Для будущих провайдеров секреты будут ссылаться на переменные окружения через `api_key_env`; само значение ключа не нужно хранить в YAML или коммитить. Текущий mock-провайдер не использует API-ключ.

Пример ссылки на секрет для будущего адаптера:

```yaml
connections:
  - name: my-provider
    provider: openai-compatible
    model: my-model
    base_url: https://example.invalid/v1
    api_key_env: MY_PROVIDER_API_KEY
```

Этот тип провайдера приведён как пример будущей конфигурации и пока не реализован. В текущем MVP зарегистрирован только `mock`.

## API и ограничения текущего MVP

- `GET /health` — проверка процесса.
- `POST /v1/chat/completions` — принимает `model` и непустой массив `messages`.
- `model` может быть именем подключения из YAML или настроенным model ID.
- Пока работает только явный выбор подключения; автоматический выбор и fallback не реализованы.
- Mock поддерживает только простые текстовые сообщения, без streaming, tools и мультимодального содержимого.
- API-совместимость на этом этапе означает минимальную форму запроса/ответа, а не полную совместимость со всеми клиентами OpenAI.
- Не выставляйте сервер в публичную сеть: аутентификация клиента и TLS пока не реализованы.
